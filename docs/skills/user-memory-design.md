# user-memory-design 设计说明

## 1. 它要解决的到底是什么

让 Agent 跨会话提供个性化服务，需要一层持久的用户记忆。它**不保存每句对话**，而是用额外的 LLM 调用**提取、压缩并审查**对未来有用的事实——这与只在当前窗口生效的上下文学习不同。

真正的难点不在「存下来」，而在四件事：**存什么**（提取的选择性/抽象化/结构化）、**怎么存**（粒度与结构的取舍）、**怎么取**（多维检索与时间感知）、**怎么收缩**（压缩、淘汰与脱敏）。

## 2. 为什么开篇就给「三套正交的分类体系」

这是本篇最重要的设计决定。记忆设计有三个独立维度，混在一起讨论必然混乱：

| 分类体系 | 回答 | 类别 |
| --- | --- | --- |
| 记忆层次 | 存在哪里 | 轨迹 / 用户长期记忆 / 业务状态 |
| 存储格式 | 怎么存 | Simple / Enhanced Notes / JSON Cards / Advanced JSON Cards（+ User as Code） |
| 认知类型 | 存什么 | 情景 / 语义 / 程序 |

**三者正交、可自由组合**：一条「偏好靠窗座位」的语义记忆可以用 Simple Notes 存；一段「先搜直飞 → 确认座位 → 用常旅客号」的程序记忆可以用 Advanced JSON Cards 存。

把这张表放在 SKILL.md 最前面，是为了让后面每一步决策都有坐标：**选格式取决于工程需求（简单性 vs 表达力），选类型取决于业务场景（要记事实、事件还是流程）**。

## 3. 主流程为什么是这 9 步

| 步骤 | 为什么放在这个位置 |
| --- | --- |
| 1 确立评估标准 | **先有标尺**：没有三层次框架，后面无法判断方案好坏 |
| 2 划分记忆层次 | 先定边界（轨迹 append-only vs 长期记忆可改写） |
| 3 确定存什么 | 提取三规则 + 认知类型分类 |
| 4 确定怎么存 | 格式选型（多为混合模式） |
| 5 确定写入策略 | 追加 vs 覆盖——决定历史是否可丢失 |
| 6 确定检索策略 | 多信号融合，时间感知是关键差异点 |
| 7 确定压缩与淘汰 | 没有压缩就会记忆爆炸 |
| 8 确定隐私与脱敏 | 越个性化风险越高，必须本地完成 |
| 9 验收 | 三层次评测 + LLM-as-a-judge |

**顺序逻辑**：标尺 → 边界 → 内容 → 格式 → 写入 → 检索 → 收缩 → 合规 → 验证。

第 1 步前置是有意的：记忆系统的「好」很难直觉判断（记住了但检索不到、记住了旧的当成现在的），必须先建立可度量的三层次框架。

## 4. 为什么默认「仅追加 + 检索时推理」

Mem0 从 v2（写入时消歧：ADD/UPDATE/DELETE/NOOP）演进到 v3（一次抽取、只做 ADD、检索时融合语义+BM25+实体+时间排序），LoCoMo 从 71.4 提升到 92.5。

**默认推荐 v3 路线的理由**：写入时的 UPDATE/DELETE 一旦判断错误，历史**不可逆丢失**；而追加路线保留全部事实、减少 LLM 调用，靠时间与相关性在检索时裁决。对记忆这种「错了很难发现」的数据，保守策略更合适。

代价要写清：库里会并存矛盾事实，检索必须能按时间取当前值。

## 6. 三个脚本的分工

| 脚本 | 为什么需要它 |
| --- | --- |
| `discover_memory_context.py` | 勘察项目：已有记忆实现、存储后端、检索与脱敏现状 |
| `memory_lint.py` | 记忆库体检：裸 PII、缺来源/时间戳、重复、原子性、该保护未保护 |
| `importance_scoring.py` | 压缩阈值必须算：访问频率 + 时间衰减 + 情感强度 + 信息独特性 |

`memory_lint.py` 的实现细节值得一提：中文重复检测用**二元组**而非按空格分词（中文没有空格，按词切会导致「偏好靠窗座位」与「偏好靠窗的座位」判不出相似）；PII 分级——身份证/银行卡/密码/密钥为 ERROR，手机号/邮箱为 WARN（是否允许明文取决于业务）。

## 7. 关键取舍

| 取舍 | 选择 | 理由 |
| --- | --- | --- |
| 格式 | 混合模式（关键少量用高表达力，大量非关键用低成本） | 一刀切必然在某个方向吃亏 |
| 写入 | 默认仅追加 | 错误覆盖不可逆丢历史 |
| 检索 | 语义 + BM25 + 实体 + 时间融合 | 单信号会漏（「现在住在哪」必须靠时间） |
| 需要「算」的操作 | 下沉到代码（User as Code） | 聚合、冲突检测、护照到期预警交给确定性函数 |
| 脱敏位置 | 本地 | 日志发到云端脱敏等于已泄露 |
| 低频关键记忆 | 加保护标记不参与淘汰 | 护照号、过敏史访问少但绝不能丢 |

## 8. 与相邻 skill 的关系

- 与 `agent-status-design`：状态栏管**单次会话**的运行时状态，User as Code 管**跨会话**的用户事实；两者都遵循「统计交给代码」。
- 与 `rag-design`：记忆量增长后，检索层就是 RAG 问题——混合检索、重排序、recall@k 那套方法可以直接复用。
