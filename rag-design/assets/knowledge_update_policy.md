# 知识更新策略

使用说明：知识库上线后会持续收到新信息。**只更新不整理会越积越乱，只定期重写又来不及。** 本表把两条路径（事件触发的增量更新 + 周期触发的全量整理）以及失效下线、权限隔离固化为策略。

---

## 1. 三层分离与版本来源

| 层 | 内容 | 可变性 | 存储 |
| --- | --- | --- | --- |
| 原始证据层 | 对话、轨迹、原始文档 | append-only | {{对象存储 / 日志系统}} |
| 知识层 | 提炼后的 Markdown / 代码 | 经 PR 修订 | {{Git 仓库：______}} |
| 服务层 | 检索索引（分块/摘要/向量） | 可重建 | {{索引：______}} |

PR 必填字段：证据标识 ______ · 知识库版本 ______ · 审核意见 ______ · 最终决定 ______

> 原则：**索引是可重建的派生物，Git 中已审核的知识才是唯一来源。**

## 3. 全量整理（周期触发）

| 项 | 配置 | 说明 |
| --- | --- | --- |
| 触发条件 | {{时间周期：每周/每月；或新增条目数/冲突数/检索质量下降超阈值}} | {{}} |
| 三项核心工作 | ① 去重去旧合并 ② 回原始数据核查 ③ 冲突解决与场景限定 | ②必须逐段对照原始证据 |
| 分批扫描 | {{按目录/时间/主题}} | **必须保留覆盖清单**，确保覆盖全量 |
| 冲突处理 | 两者都有效 → 写入各自适用场景；证据不足 → 保留待确认 | **不强行收敛** |
| 产物形式 | 分支提交重组 diff，可按目录拆多个 PR | 共享同一份整理计划与覆盖清单 |
| 合并后验证 | 重建索引 + **回放典型检索问答用例** | 确认知识没有变得不可见 |

## 4. 失效内容下线

| 项 | 配置 | 说明 |
| --- | --- | --- |
| 元数据字段 | version / effective_from / effective_to | 每个分块必带 |
| 下线方式 | {{检索阶段过滤已失效内容 / 摘要显式标注「已于某日废止」}} | {{}} |
| 新版与旧版关系 | 旧版保留但标记失效，不直接删除 | 便于追溯与回滚 |

## 5. 权限与租户隔离

| 项 | 配置 | 说明 |
| --- | --- | --- |
| 权限过滤位置 | {{检索层（必选）}} | 越权内容不得进入任何用户上下文 |
| 租户隔离 | 向量索引与元数据按租户隔离 | 避免「串味」 |
| 审核范围边界 | Proposer/Reviewer 只能访问其被授权的租户范围 | 审核不突破隐私边界 |

## 6. 检查清单

- [ ] 知识库已纳入 Git，无模型可直接改主库
- [ ] Proposer/Reviewer 异源且权限分工明确
- [ ] 最大迭代与成本预算已设，超出转人工
- [ ] 分块带版本与生效/失效时间
- [ ] 检索层按权限过滤，租户索引隔离
- [ ] 定期整理含回原始数据核查与覆盖清单
- [ ] 结构化变更后回放过典型用例
