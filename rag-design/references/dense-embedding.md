# 稠密嵌入：从词汇关联到语义理解

## 1. 什么是嵌入

计算机只能处理数字，不能直接理解「苹果」和「橙子」的含义。嵌入的思路是：**把每个词或句子转化成一串数字（向量）**，并且让语义相近的内容转化出来的数字串也「相近」。

这些向量所在的空间称为**向量空间**：可以想象成一张高维地图，每个词或句子是其中一个点，语义越接近的内容彼此越靠近——如同地图上北京与上海的位置反映它们的地理相关性。

经典例子：`"国王" - "男性" + "女性" ≈ "女王"`，说明向量运算可以捕捉语义关系。

**「稠密」是相对稀疏嵌入而言**：稠密向量每个维度都有数值，稀疏向量大部分维度为零。

## 2. 余弦相似度：为什么用夹角而不是距离

衡量两个向量有多「近」，常用**余弦相似度**：计算两个向量夹角的余弦值，越接近 1 表示方向越一致、语义越相似。

**为什么用夹角**：因为关心的是两个向量的**方向是否一致**（语义是否相近），而不是它们的**长度**（文本长度或词频）。两篇内容相同但长度不同的文档，向量长度不同但方向一致，余弦相似度能正确判断它们语义相同。

直觉例子：养猫相关的两个表达在向量空间中几乎重合（余弦接近 1），而养猫与股票投资方向迥异（余弦接近 0）。实际模型使用 768 维甚至更高维度，但判断原理相同。

计算：

\[
\cos(\theta) = \frac{A \cdot B}{|A| \times |B|}
\]

手算示例（简化 3 维）：
- A「如何养猫」= (0.9, 0.5, 0.1)，B「猫咪饲养指南」= (0.8, 0.6, 0.1) → cos ≈ **0.99**（非常相似）
- A 与 C「股票投资策略」= (0.1, 0.1, 0.9) → cos ≈ **0.25**（差异很大）

## 3. 技术演进

| 模型 | 年份 | 维度 | 特点 |
| --- | --- | --- | --- |
| Word2Vec | 2013 | 300 | 静态词向量，捕捉共现关系，预测式训练 |
| GloVe | 2014 | 300 | 全局统计 + 矩阵分解 + 共现 |
| BERT | 2018 | 768 | 上下文感知，Transformer，MLM 预训练 |
| Sentence-BERT | 2019 | 768 | 句子级嵌入，孪生网络对比学习 |
| BGE-M3 | 2024 | 1024 | 多语言、长文本，多阶段混合训练；**同时输出稠密、稀疏、多向量三种表示** |

分水岭：**静态词向量（一词一向量）→ 上下文感知嵌入（一词多向量）**。

### 为什么静态词向量不够

Word2Vec 只能捕捉**词汇共现关系**，存在根本局限：**无法处理一词多义**。`bank` 在 `river bank`（河岸）与 `investment bank`（投资银行）中含义不同，但 Word2Vec 赋予完全相同的向量。

现代模型（BERT、BGE-M3）通过**自注意力机制**在生成一个词的向量时参考句子中所有其他词的信息，因此「苹果公司发布新产品」与「买了两斤苹果」中的「苹果」得到不同向量。

补充：BERT 这类较早的上下文模型输入长度上限仅 512 token，**不适合长文本**；BGE-M3 等新一代模型支持多语言与长文本。

## 4. 大规模检索：ANN 索引

当知识库有上百万条文档时，逐一计算相似度太慢。**ANN（Approximate Nearest Neighbor，近似最近邻）**通过索引结构实现近似但极快的查找。

### HNSW 结构要点

分层图：Layer 0 稠密全节点，Layer 1 中等密度，Layer 2 稀疏长程连接。搜索从顶层开始，逐层向下精炼；支持增量更新、高召回率、O(log N) 查询复杂度。

### ANNOY 与 HNSW 对比

| 特性 | ANNOY（基于树） | HNSW（基于图） |
| --- | --- | --- |
| 构建速度 | 快 | 较慢 |
| 内存占用 | 低 | 较高 |
| 增量更新 | 不支持（需完全重建） | 支持（长期增量插入后建议定期重建以保持查询精度） |
| 查询精度 | 较高 | 极高 |
| 适用场景 | 数据不常变的静态数据集 | 需要实时索引新信息的动态场景 |

**选择合适的索引策略与选择嵌入模型同等重要**，它直接决定系统的性能、成本和可维护性。

## 5. 选型决策表

| 条件 | 推荐 |
| --- | --- |
| 数据基本静态、内存紧张 | ANNOY |
| 需要实时写入新文档 | HNSW（并规划定期重建） |
| 多语言、长文本 | BGE-M3 类模型（注意其可同时产出稀疏表示） |
| 只做短文本语义匹配 | 句向量模型（Sentence-BERT 类）即可 |
| 需要可解释的关键词匹配 | 必须再配一路 BM25（见 `sparse-embedding.md`） |

## 6. 自检

- [ ] 明确用余弦相似度（而非欧氏距离）作为度量
- [ ] 嵌入模型支持目标语言与文本长度
- [ ] 索引类型与数据更新频率匹配
- [ ] 已规划增量写入后的索引重建策略
- [ ] 向量维度与存储、内存预算已核算
- [ ] 稠密路之外配有稀疏路（混合检索）
