# 稀疏嵌入：精确匹配的关键词检索

与捕捉语义相似性的稠密嵌入不同，**稀疏嵌入**根植于传统信息检索，核心是**精确的关键词匹配**。它将文档表示为极高维向量，绝大多数维度为零，只有与文档中出现词汇对应的维度非零。

## 1. 理论基础：词袋模型

**词袋模型（Bag of Words, BoW）**把文本看作「装满词的袋子」：只关心哪些词出现了、出现几次，**完全忽略词序**。因此「猫追狗」与「狗追猫」在词袋模型中完全相同。

在此基础上发展出更复杂的**词项加权与排序算法**：TF-IDF → BM25。

## 2. TF-IDF

核心直觉：**一个词在当前文档中出现得越多、在整个语料库中越少见，它对检索越重要**。

例如 100 篇文章中 60 篇包含「模型」，只有 3 篇包含「蒸馏」，那么「蒸馏」更能区分哪些文章真正与「模型蒸馏」相关。

\[
\text{TF-IDF}(t, d) = \text{TF}(t, d) \times \text{IDF}(t), \quad \text{IDF}(t) = \ln\frac{N}{\text{DF}(t)}
\]

- TF(t,d)：词 t 在文档 d 中出现次数
- DF(t)：包含该词的文档数
- N：文档总数

**两个局限**：
1. 原始词频随出现次数**线性增长**——出现 10 次是 5 次的两倍。
2. **没有校正文档长度**——长文档仅因字数更多就容易获得高分。

## 3. BM25：对两个局限的经典修正

\[
\text{Score}(Q, D) = \sum_i \text{IDF}_{BM25}(q_i) \cdot \frac{\text{TF}(q_i, D)(k_1 + 1)}{\text{TF}(q_i, D) + k_1\left(1 - b + b \cdot \frac{|D|}{avgdl}\right)}
\]

其中 \(q_i\) 是查询中的词，\(|D|\) 是文档长度，\(avgdl\) 是语料库平均文档长度。

### 三个组成部分

| 组成 | 作用 | 参数 |
| --- | --- | --- |
| **IDF** | 衡量词的稀有度：「的」≈ 0，「量刑」≈ 5.2；稀有词权重远大于常见词 | — |
| **词频饱和（TF）** | 出现次数翻倍，得分**不会**线性翻倍；边际贡献递减 | `k1` 控制饱和速度 |
| **长度归一化** | 相同词频在较长文档中权重更低，避免长文档偏倚 | `b ∈ [0,1]`：b=0 不考虑长度，b=1 完全归一化 |

常用默认值：**k1 = 1.5，b = 0.75**。

### IDF 的 BM25 写法与下限

\[
\text{IDF}_{BM25}(t) = \ln\frac{N - \text{DF}(t) + 0.5}{\text{DF}(t) + 0.5}
\]

与 TF-IDF 的 IDF **不是同一个公式**。直觉不变（词越稀有权重越高），变的只是度量方式：
- 分子从「文档总数 N」换成「**不含**该词的文档数 N − DF(t)」，比值直接反映「不含该词的文档是含它的文档的多少倍」；
- 分子分母各加 0.5 做**平滑**，使 DF(t) 取 0 或 N 两个极端时公式仍有定义。

**实现注意**：当词出现在超过半数文档中（DF(t) > N/2）时取值变为**负数**，因此实现中通常**设一个下限**。

## 4. 倒排索引：稀疏检索为什么快

**倒排索引（Inverted Index）**是从词到文档的反向映射表：
- 普通索引：给定文档，列出它包含的词。
- 倒排索引：**给定一个词，立刻找到所有包含它的文档**。

好比书后的术语索引页：查「TCP」，它告诉你第 45、112、203 页提到了这个词。

构建流程：文本预处理（分词、去除「的」「了」等停用词）→ 构建倒排索引 → 计算 TF 与 IDF。

## 5. 手算示例（可直接用脚本复现）

示例语料 N=10，参数 k1=1.5、b=0.75、avgdl=250，查询「模型 蒸馏」：

```text
词 "模型" → 命中 3 篇 (df=3, IDF=ln((10−3+0.5)/(3+0.5))=0.76):
  doc_1: TF=5, 长度 200 → 贡献 1.52
  doc_3: TF=2, 长度 500 → 贡献 0.82
  doc_7: TF=8, 长度 150 → 贡献 1.68
词 "蒸馏" → 命中 2 篇 (df=2, IDF=ln((10−2+0.5)/(2+0.5))=1.22，比"模型"更稀有):
  doc_1: TF=3, 长度 200 → 贡献 2.15   ← 更稀有，单次出现贡献更大
  doc_5: TF=1, 长度 250 → 贡献 1.22

最终排序: doc_1 (3.67) > doc_7 (1.68) > doc_5 (1.22) > doc_3 (0.82)
```

两点结论：
1. **稀有词贡献更大**：doc_1 中「蒸馏」TF=3 低于「模型」TF=5，但因 IDF 更高，贡献（2.15）反超「模型」（1.52）——这正是 BM25 的核心逻辑。
2. **多词命中叠加**：doc_1 同时命中两个查询词，总分遥遥领先。

用 `scripts/bm25_calc.py` 可复现这一计算过程（输出分步日志）。

## 6. 优势与局限

| 优势 | 局限 |
| --- | --- |
| 精确关键词匹配，在**技术代码、人名、专有名词**等查询上表现极佳 | 读不懂同义表达：查一个词只能匹配字面相同的文档（搜 `kitty` 找不到只写 `cat` 的文档） |
| 可解释（能看到是哪个词命中） | 无法捕捉语义相似 |
| 倒排索引使其极快 | 依赖分词质量（中文需分词或使用 n-gram） |

**这种优势与局限的对照，正是引入混合检索的实践基础。**
