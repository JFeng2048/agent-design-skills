# 记忆压缩、整理与隐私保护

随着交互持续进行，记忆系统面临**存储空间**与**检索效率**的双重挑战。简单的累积式存储会导致记忆爆炸，既消耗存储，也降低检索准确性。同时，记忆越个性化，隐私风险越高。

## 1. 第一层：重要性评分筛选

综合四个因素给每条记忆打分，**低于阈值**的标记为可压缩或可删除：

| 因素 | 方向 | 说明 |
| --- | --- | --- |
| 访问频率 | 正向 | 经常被检索的记忆更重要 |
| 时间衰减 | 负向 | 越久远的记忆越容易被遗忘 |
| 情感强度 | 正向 | 带有强烈情感标记的记忆更易保留 |
| 信息独特性 | 正向 | 重复信息的重要性降低 |

示例对比：

- 被访问 5 次、创建于 3 天前、带强情感标记、无重复记录的记忆 → **高重要性**。
- 仅被访问 1 次、创建于 90 天前、无情感标记、与其他 3 条记忆高度重复 → **低于压缩阈值**。

阈值与权重用 `scripts/importance_scoring.py` 测算，并结合业务调整。

## 2. 第二层：聚类

- 相似记忆被**分组**，每组生成**代表性摘要**。
- 例：多次天气对话压缩为「用户经常询问天气，特别关心降雨」。
- **原始详细记忆可存档到二级存储**，需要时可回溯。

聚类依据：语义相似度 + 实体重合度 + 时间邻近度。

## 3. 第三层：抽象与泛化

从具体**情景记忆**中提取一般性规律，转化为**语义或程序记忆**。

- 例：从多次购物对话中学到「偏好性价比高的产品，重视用户评价」→ 语义记忆。
- 例：从多次订票过程中抽象出「先搜直飞 → 确认座位 → 用常旅客号」→ 程序记忆。

这一层是记忆系统「越用越聪明」的关键：不是越存越多，而是**越存越抽象**。

## 4. 三层压缩的触发时机

| 层 | 触发 | 成本 | 副作用 |
| --- | --- | --- | --- |
| 重要性评分 | 每次检索后更新计数，定期批量评分 | 低 | 可能误删低频但重要的记忆（如护照号） |
| 聚类 | 记忆量达到阈值或按周期 | 中（需 LLM 生成摘要） | 摘要可能丢失细节（原始存档可缓解） |
| 抽象泛化 | 按类别积累到一定数量后 | 中高 | 泛化错误的规律会长期误导 |

**关键提醒**：低频但关键的记忆（证件号、过敏史、禁忌）必须加**保护标记**，不参与压缩淘汰。

## 5. 隐私保护：日志脱敏

核心挑战：让 Agent 既能利用用户信息提供个性化服务，又不让敏感数据暴露在 LLM 上下文和系统日志中。

### 5.1 本地小模型脱敏

实验方案（log-sanitization 项目）：通过 Ollama 调用**本地 Qwen3 0.6B** 小模型（可在 CPU、消费级设备运行，也可切换到 qwen3:1.7b、qwen3:4b 等更大规格）实现 PII 检测与脱敏。

**为什么本地部署**：日志本身可能包含敏感信息，**发送到云端脱敏就违背了隐私保护的初衷**。

### 5.2 覆盖范围

| 类型 | 例子 |
| --- | --- |
| 结构化 | 身份证号、银行卡号 |
| 半结构化 | 地址 |
| 自然语言 | 「我的密码是 abc123」 |

识别结果通过 **JSON Schema 结构化输出**，包含敏感信息类型、位置和置信度。

### 5.3 效果与混合策略

- 相比传统正则表达式，基于 LLM 的脱敏**召回率达 95% 以上**，同时显著降低**假阳性**。
- 超高吞吐场景用**混合策略**：正则快速过滤明显模式，LLM 深度分析剩余文本。

### 5.4 脱敏位置

| 位置 | 说明 |
| --- | --- |
| 写入前 | 日志落盘前脱敏，避免敏感信息进入存储 |
| 提取前 | 喂给 LLM 做记忆提取前脱敏，避免进入模型上下文 |
| 检索返回时 | 按调用方权限决定是否返回原始值或掩码值 |

**默认原则**：原始敏感值不出本机；记忆中只存掩码或引用，需要时从受控存储按需取回。

## 6. 保留期限与遗忘权

- 明确每类记忆的**保留期限**（如事件记忆 1 年、画像长期）。
- 提供**导出**与**删除**能力，响应用户的遗忘权请求。
- 删除需覆盖：长期记忆库、只增日志、向量索引、备份。

- [ ] 聚类摘要有原始存档可回溯
