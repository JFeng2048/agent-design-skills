# 记忆能力的评估：三层次框架

动手设计记忆系统前先回答「什么样的记忆系统算好」，后面讨论各种方案时才有统一标尺。

## 1. 八项记忆能力（归纳口径）

综合 LoCoMo 等公开基准与商业记忆产品实践，用户记忆能力可归纳为八项：

| 能力 | 说明 |
| --- | --- |
| 个人信息保留 | 记住用户身份等长期个人信息 |
| 偏好追踪 | 跟踪并记住用户的长期偏好 |
| 上下文切换 | 多个话题之间切换时保持连贯 |
| 记忆更新 | 用户提供与旧信息矛盾的新信息时能正确处理 |
| 多会话连续性 | 跨会话保持知识 |
| 复杂思考 | 基于多个记忆片段联合思考（如对花生过敏时推荐泰国菜主动提醒花生成分） |
| 时间感知 | 记住日期、理解相对时间、进行时间计算 |
| 冲突解决 | 识别并处理记忆之间的不一致 |

参考基准：**LoCoMo**（Long-term Conversational Memory）构造平均约 300 轮、最多 35 个会话的超长多轮对话，通过问答（单跳、多跳、时间推理、开放域、对抗性）、事件摘要、多模态对话生成三类任务考察长程记忆与理解能力。

## 2. 三层次评估框架

八项能力之外，更贴合 Agent 场景的是**三个递进层级**：

### 第一层：基础回忆

最根本的能力——准确存储和检索用户**直接提供的、结构化的、无歧义**的信息。

- 例子：「我的会员号是 12345」→ 后续需要时精确返回。
- 意义：确保记忆系统的基本可靠性，是后续更复杂能力的基础。
- 用例特征：通常由**单个会话**构成。

### 第二层：多会话检索

面对来自**不同对象、不同时期**的多段会话时，能检索出所有相关信息并推理判断。

真实交互往往不是一次性完成的，而是通过不同渠道或在不同时间分别完成。典型用例：

| 场景 | 期望行为 |
| --- | --- |
| 拥有两辆车的用户要求「为我的车预约保养」 | 找出两辆车全部信息，**主动询问**为哪辆服务，而不是随便猜一辆 |
| 询问贷款状态 | 分辨正在履行的**有效合同**，忽略过去咨询但未生效的报价 |
| 取消「洛杉矶之旅」 | 理解旅行是**复合事件**，主动关联所有相关预订（机票 + 酒店） |

### 第三层：主动服务

衡量是否达到「助理」水准的最高标准：综合多个会话甚至很久以前的信息，提供**预见性**帮助，从看似无关的记忆中发现深层联系，且**在没有明确指令的情况下**主动规避问题、整合信息。

| 场景 | 期望行为 |
| --- | --- |
| 预订国际航班 | 主动关联数月前存储的护照信息，发现即将过期并预警 |
| 手机损坏 | 主动整合所有保障方案（自带保修、信用卡附加保修、运营商保险），给出完整选项列表 |
| 报税季 | 主动从过去一年记录中搜寻整合所有税务文件（股票销售、自由职业收入、房产税），呈现完整待办清单 |

## 3. 评测集构造与流程

- **规模**：每层各 20 个测试用例；每个用例包含大量事实细节。
- **构成**：第一层用例通常由单个会话构成；第二、三层用例由多个跨时间、跨对象的会话构成（每个用例合计约 50 轮沟通）。
- **流程**：
  1. 被测 Agent 根据第一个会话**生成记忆**；
  2. 根据记忆和下一个会话**修改记忆**——**仅能访问记忆，不可回看之前会话的原始对话**；
  3. 重复直到该用例所有会话处理完毕；
  4. 记忆生成完毕后，要求 Agent **根据记忆回答一个新的用户问题**；
  5. 用 **LLM-as-a-judge**（另一个 LLM 当评委）对回答与参考答案对比，得到该用例的奖励得分。

关键约束是第 2 步：不可回看原始对话。这迫使记忆本身成为唯一信息源，才能真实衡量记忆质量而非长上下文能力。

## 4. 怎么用这个框架做设计决策

| 若业务主要需要 | 设计重点 |
| --- | --- |
| 第一层 | 简单格式即可（Simple Notes / JSON Cards），保证写入准确与精确检索 |
| 第二层 | 必须有多维检索（实体 + 时间）、复合事件关联、消歧字段 |
| 第三层 | 需要类型化状态与规则执行（见 `executable-memory.md`）+ 主动触发机制 |
| 全部 | 混合模式：低成本格式承载量，高表达力格式承载关键关系 |
