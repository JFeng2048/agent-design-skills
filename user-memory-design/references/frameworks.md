# 记忆框架案例：Mem0 与 Memobase

开源社区已有多个专门的记忆管理框架。这里以两个为例，看不同设计理念如何取舍。

## 1. Mem0：从写入时消歧到检索时推理

### v2（2025 论文）：提取 → 对比 → 决策

```
Dialogue
  → LLM extract candidate facts
  → Vector search existing memory
  → LLM decide: ADD · UPDATE · DELETE · NOOP
```

- 对话结束后，LLM 先抽取候选事实；
- 系统用向量检索找到相近的已有记忆；
- 由 LLM 在 ADD、UPDATE、DELETE、NOOP 中做出决定。

例子：用户先说「我住在北京」，后来又说「我搬到了上海」→ 系统将前一条 **UPDATE** 为「住在上海」，在**写入时消除冲突**。

变体：**Mem0-g** 用实体—关系图支持多跳与时序问题（应理解为**历史设计**，见下文 v3 说明）。

| 优点 | 风险 |
| --- | --- |
| 记忆库始终简洁一致 | 一次错误的更新或删除会**不可逆丢失历史** |
| | 每条候选事实都要经历检索 + **第二次 LLM 判断**（成本高） |

### v3（2026 年 4 月）：仅追加写入 + 混合检索

```
Dialogue
  → 1× LLM extract（single pass）
  → ADD-only store（preserve history）
  → Hybrid retrieval: semantic · BM25 · entity · time
  → Top-k ranked facts
```

- 用**一次** LLM 调用抽取事实，并且**只做 ADD**；
- 「住在北京」和稍后的「搬到上海」作为**带时间信息的两条事实并存**；
- 查询时融合**语义相似度、BM25 关键词、实体匹配**，并结合**时间信息**排序；
- Agent 确认完成的动作也成为一等事实。

效果：避免错误 UPDATE/DELETE 丢失历史，减少 LLM 调用，还能用多检索信号与时间排序找出当前事实。

**收益数据**：LoCoMo 71.4 → 92.5（+21.1）；LongMemEval 67.8 → 94.4（+26.6）。

注意：当前 OSS 已**移除外部图存储及 relations 返回值**，实体链接仅用于内部检索加权；因此 **Mem0-g 应理解为历史设计**。版本差异以官方迁移指南为准——**不要凭记忆判断框架能力**。

## 2. Memobase：用户画像 + 事件记忆

开源项目 `memodb-io/memobase`。设计理念：与其做通用记忆流水线，不如**聚焦「用户画像」这一具体形态**。

| 组成部分 | 说明 |
| --- | --- |
| **用户画像**（Profile） | 一组**可由开发者配置的槽位**，按主题 → 子主题两级组织（`basic_info→姓名`、`interest→兴趣偏好`、`work→职位`），存放从对话中提取的稳定用户属性；开发者可精确控制画像的范围和粒度 |
| **事件记忆**（Event Memory） | 按**时间线**记录用户经历的事件，用于回答「我们上次讨论预算是什么时候」这类与时间有关的问题 |

工程特点：**缓冲批处理**——对话先在缓冲区累积，达到一定规模或时限后再统一触发一次记忆提取，以**摊薄 LLM 调用成本**；查询侧只需读取已整理好的画像与事件，保证**低延迟**。

## 3. 两个框架的覆盖与取舍

| 框架 | 覆盖的记忆类型 | 特点 |
| --- | --- | --- |
| Mem0 | 事实条目 ≈ **语义记忆** | 通用流水线，v3 走 ADD-only + 混合检索 |
| Memobase | 画像 ≈ **语义记忆**，事件记忆 ≈ **情景记忆** | 画像槽位可配置 + 批处理摊薄成本 |

两者各自只覆盖了记忆设计空间的一部分。把视野放宽，可按认知科学分类设想**多类型记忆协同的参考架构**（见 `memory-types.md` 第 6 节）。

## 4. 自建 vs 用框架

| 考虑 | 倾向 |
| --- | --- |
| 需求为标准的用户画像 + 事件时间线 | 用成熟框架，聚焦业务槽位设计 |
| 需要复杂的跨实体关系与消歧 | 自建 Advanced JSON Cards 或类型化状态 |
| 需要聚合 / 冲突检测 / 约束执行 | 自建可执行状态（见 `executable-memory.md`） |
| 成本敏感、调用量大 | 批处理 + ADD-only，减少 LLM 调用 |
| 合规要求严格（数据不出域） | 自建或私有化部署，脱敏在本地完成 |
