# 存什么：认知科学的三类记忆

前面解决了「放哪里」（层次）与「怎么存」（格式），本节回答「存什么」。

## 1. 工作记忆与长期记忆

认知科学把记忆划分为：

- **工作记忆**（Working Memory）：对应 Agent 的**上下文窗口**——处理当前任务的临时信息空间。轨迹是其最核心的内容，但也可能包含从长期记忆**激活加载**的信息。
- **长期记忆**：细分为三种类型，每种在 Agent 记忆中都有直接对应。

## 2. 三类长期记忆

| 类型 | 定义 | 人类例子 | Agent 对应 |
| --- | --- | --- | --- |
| **情景记忆**（Episodic） | 关于具体事件和经历的记忆 | 「上周三和同事在那家意大利餐厅吃了一顿很棒的晚餐」 | 「用户订了下周五去东京的 ANA 航班」——记录具体事件的时间、对象、细节 |
| **语义记忆**（Semantic） | 从具体事件中抽象出的一般性知识 | 「意大利的首都是罗马」 | 「用户是素食者」「用户偏好靠窗座位」——从多次交互提炼的稳定特征 |
| **程序记忆**（Procedural） | 关于行为模式和流程的记忆 | 骑自行车的能力 | 「先搜索直飞 → 确认座位偏好 → 使用常旅客号 → 订餐」——从反复订票学到的通用流程 |

## 3. 三套分类体系的关系（表 3-1）

| 分类体系 | 回答的问题 | 具体类别 |
| --- | --- | --- |
| 记忆层次 | **存在哪里？** | 轨迹（当前会话）、用户长期记忆（跨会话）、业务状态（任务阶段） |
| 存储格式 | **怎么存？** | Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards |
| 认知类型 | **存什么？** | 情景记忆（具体事件）、语义记忆（一般知识）、程序记忆（行为流程） |

三套体系**正交，可自由组合**：

- 一条「用户偏好靠窗座位」的**语义记忆**，可以用 **Simple Notes** 格式存储在**用户长期记忆**中；
- 一段「先搜直飞 → 确认座位 → 用常旅客号」的**程序记忆**，可以用 **Advanced JSON Cards** 格式存储。

**选择哪种格式取决于工程需求**（简单性与表达力的取舍）；**选择存什么类型取决于业务场景**（需要记住事实、事件还是流程）。

## 4. 提取的三条规则

无论存哪种类型，提取结果都应同时满足：

| 规则 | 说明 | 反例 → 正例 |
| --- | --- | --- |
| **选择性** | 丢弃短期细节 | 丢弃「搜索返回 3 个选项」这类过程性信息 |
| **抽象化** | 把本次具体信息归纳为长期特征 | 「本次航班选了靠窗」→「用户偏好靠窗座位」 |
| **结构化** | 用可检索的字段保存事实 | 存成 `{category: preference, key: seat, value: window}` 而非一句话 |

示例（订东京机票的对话）：

```text
User: Help me book a flight to Tokyo next Friday. I prefer window seats
      and I'm vegetarian, so I'll need a special meal.
...
User: Yes, and use my United MileagePlus number 12345678.
```

提取结果：

```text
- User prefers window seats                        (preference，语义记忆)
- User is vegetarian, needs special meals on flights (dietary restriction，语义记忆)
- User's United MileagePlus number: 12345678        (loyalty program，语义记忆)
- User has travel plans to Tokyo                    (recent activity，情景记忆)
```

注意「搜索返回 3 个选项」没有被记住——这正是选择性的体现。

## 5. 各类别的存储建议

| 类型 | 推荐格式 | 理由 |
| --- | --- | --- |
| 情景记忆 | JSON Cards / Enhanced Notes + **丰富元数据**（时间戳、情感标记、任务标识） | 需按时间、主题等多维组合检索（「我们上次讨论预算是什么时候」） |
| 语义记忆 | Simple Notes / JSON Cards | 稳定、原子、需要精确命中 |
| 程序记忆 | Advanced JSON Cards / 可执行代码 | 需带来源与适用场景，可复用执行 |

## 6. 多类型记忆协同的参考架构

这是对**设计空间的概括**，而非某个具体项目的实现：

```text
工作记忆（当前任务状态）
   ↑ 选择性转移        ↓ 激活加载
┌──────────────────────────────────────────┐
│ 长期记忆（跨会话）                        │
│   情景记忆：带元数据的事件序列             │
│   语义记忆：抽象出的一般知识               │
│   程序记忆：可复用的行为流程               │
└──────────────────────────────────────────┘
```

参考架构在此之上真正新增的重点，是**情景记忆的多维元数据检索**：存储带有丰富元数据（时间戳、情感标记、任务标识）的事件序列，可按时间、主题等多个维度组合检索。

实际框架往往只实现其中一两种类型——**按业务需要取舍，比追求「大而全」更符合工程现实**。

- [ ] 程序记忆带适用场景，能被调用执行
- [ ] 已明确本业务需要哪几类（不追求全都要）
